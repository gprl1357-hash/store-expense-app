# 개선요청(피드백) 채널 아키텍처 제안

> **상태:** ✅ **1단계 MVP 구현 완료 (dev 브랜치, 텍스트+사진, 운영 미반영)**
> **목표:** 사용자(매장 직원)가 언제든지 글·사진·동영상으로 개선사항/문제를 제보하고,
> 관리자(사용자 본인)가 **즉시** 알림을 받는 채널 마련

---

## 1. 요구사항 정리

| 항목 | 내용 |
|---|---|
| 제보자 | 매장 직원 (이미 로그인된 매장 세션 보유) |
| 제보 형태 | 텍스트, 사진, 동영상 (복수 첨부 가능) |
| 제보 시점 | 언제든지 — 별도 진입장벽 없이 앱 내 상시 접근 가능 |
| 즉시성 | 제보 즉시 관리자에게 알림 (실시간에 가까운 지연) |
| 관리자 확인 | 제보 내용 확인, 처리 상태 관리 |

---

## 2. 기존 아키텍처와의 연결

이번에 구축한 매장 인증 + 서버 경유 구조를 그대로 재사용합니다. 별도의 새로운 인증·전송 체계를 만들지 않습니다.

```
[제보 폼 UI]                     [서버]                          [저장/알림]
매장 세션(쿠키)로 요청  ──►  /api/feedback (POST)  ──►  Supabase: feedback 테이블 INSERT
텍스트 + 첨부파일                세션 검증(요구사항 1번과 동일)      Storage: feedback-media 버킷 업로드
                                                        Slack: 즉시 알림 (기존 지출 알림과 동일 패턴)
```

- **인증:** 기존 `store_session_*` 쿠키 검증 재사용 → 어느 매장의 누가 제보했는지 자동 기록
- **서버 경유 원칙 유지:** 클라이언트가 Supabase에 직접 쓰지 않고 API Route를 거침 (OWASP A01 대응 원칙 동일 적용)
- **즉시 알림:** 기존 Slack 지출 알림(`/api/slack/webhook`, `notify-expense`)과 동일한 방식으로 제보 즉시 Slack 채널에 전송

## 3. 데이터 모델

### `feedback` 테이블 (신규)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | UUID | PK |
| `store_id` | TEXT | 제보한 매장 (FK → stores) |
| `created_by` | TEXT | 작성자 (기존 `users` 목록 재사용) |
| `category` | TEXT | 버그/건의/기타 (선택, 필터용) |
| `message` | TEXT | 제보 내용 (텍스트) |
| `media_urls` | TEXT[] | 첨부 파일 URL 목록 (사진/동영상) |
| `status` | TEXT | `new` \| `read` \| `resolved` (기본 `new`) |
| `created_at` | TIMESTAMPTZ | 제보 시각 |
| `resolved_at` | TIMESTAMPTZ | 처리 완료 시각 (nullable) |

기존 `expenses` 테이블과 동일한 패턴(매장 FK, RLS 서버 전용)을 그대로 따릅니다.

### Storage — `feedback-media` 버킷 (신규)

기존 `expense-photos`(사진), `expense-backups`(백업) 버킷과 같은 구조로 추가합니다.

| 항목 | 사진 | 동영상 |
|---|---|---|
| 허용 타입 | `image/jpeg`, `image/png`, `image/webp`, `image/heic` | `video/mp4`, `video/quicktime` |
| 용량 제한 | 5MB (기존 `expense-photos`와 동일, 클라이언트에서 리사이즈 후 업로드) | **30~50MB** (모바일 촬영 원본 고려, 서버 업로드 시간·비용 이슈로 초기엔 짧은 클립 권장 — 예: 최대 30초) |
| 처리 | 기존 `resizeImageFile` 재사용 | 초기 단계는 리사이즈/압축 없이 그대로 업로드 (추후 서버 트랜스코딩은 별도 검토) |

> 동영상은 용량이 커서 Vercel 서버리스 함수의 요청 본문 크기 제한(기본 4.5MB, 설정에 따라 다름)에 걸릴 수 있습니다.
> **Supabase Storage의 클라이언트 직접 업로드(서명된 업로드 URL, signed upload URL)** 방식을 사용해
> 파일 자체는 브라우저 → Supabase Storage로 직접 전송하고, API Route는 업로드 URL 발급과 메타데이터
> 저장(제보 내용, 업로드된 파일 경로)만 담당하도록 설계해야 합니다. (아래 4번에 반영)

## 4. API 설계

| 엔드포인트 | 메서드 | 역할 |
|---|---|---|
| `/api/feedback/upload-url` | POST | 첨부파일용 Supabase Storage 서명된 업로드 URL 발급 (세션 검증) |
| `/api/feedback` | POST | 제보 등록 — 텍스트 + 업로드 완료된 파일 경로 목록 → DB 저장 + Slack 알림 발송 |
| `/api/feedback` | GET | (관리자용, 2단계) 제보 목록 조회 — 매장 필터 없이 전체 조회 가능해야 하므로 별도 관리자 인증 필요 (5번 참고) |
| `/api/feedback/[id]` | PATCH | (관리자용, 2단계) 상태 변경 (`read`/`resolved`) |

**제출 흐름 (사진/동영상 포함):**
1. 클라이언트: 텍스트 작성 + 파일 선택(카메라/갤러리)
2. 첨부파일마다 `/api/feedback/upload-url` 호출 → 서명된 업로드 URL 수신
3. 클라이언트가 그 URL로 파일을 **직접** Supabase Storage에 업로드 (서버 경유 없음, 대용량 우회)
4. 업로드 완료된 파일 경로들과 텍스트를 묶어 `/api/feedback`에 POST → DB 저장
5. 서버가 Slack에 즉시 알림 전송 (매장명 + 작성자 + 내용 요약 + 첨부 개수, 필요 시 사진 미리보기)

이 흐름은 기존 지출 사진 첨부(`uploadExpensePhoto`)보다 한 단계 더 안전합니다 — 동영상처럼 큰 파일이 Vercel 함수를 거치지 않아 타임아웃·비용 문제를 피합니다.

## 5. 관리자 조회 — 현실적인 단계적 접근

이 앱은 아직 "관리자(사용자 본인) 전용 로그인"이 없고, 매장 단위 로그인만 존재합니다. 개선요청 전체를 한눈에 보려면 매장을 가리지 않는 별도 권한이 필요합니다.

| 단계 | 방식 | 장단점 |
|---|---|---|
| **MVP (권장 시작점)** | Slack 알림만 — 제보가 오면 즉시 Slack 채널에 텍스트+사진 미리보기로 도착. 상세 확인/검색은 Supabase **Table Editor**에서 직접 조회 | 구현 최소화, 지금 바로 시작 가능. "즉각적인 피드백"이라는 핵심 요구사항은 이 단계만으로 충족 |
| **2단계** | 앱에 **관리자 전용 로그인**(매장 인증과 별개의 admin 계정, 예: 별도 `admin_password_hash`를 별도 테이블에 보관) 추가 → `/admin/feedback` 페이지에서 전체 매장 제보 목록·상태 관리 | 매장 인증 체계에 영향 없이 독립적으로 얹을 수 있음. UI/DB 작업 필요 |
| **3단계** | 상태 변경 시 Slack 스레드에 답글로 처리 결과 자동 기록, 매장별 미해결 건수 요약 등 | 운영 편의성 향상, 선택 사항 |

**권장:** 우선 MVP(Slack 알림 + Table Editor 조회)로 시작해 실제로 얼마나 제보가 들어오는지 확인한 뒤, 필요성이 확인되면 2단계(관리자 대시보드)를 진행하는 것이 합리적입니다.

## 6. UI 진입점

- 하단 탭(`TabNav`)에 새 탭을 추가하기보다는, 기존 4개 탭(입력/조회/설정 등) 어디서든 접근 가능한 **플로팅 버튼**(예: 우측 하단 "📢 건의하기")을 권장 — 현재 앱이 이미 탭이 여러 개라 탭을 더 늘리면 어르신 사용자에게 복잡해질 수 있음
- 제보 폼: 큰 글씨 텍스트 입력창 + "사진/동영상 추가" 버튼(`<input type="file" accept="image/*,video/*" capture>` — 모바일에서 카메라 바로 호출 가능) + 제출 버튼
- 제출 후 "접수되었습니다" 토스트 (기존 지출 등록 토스트와 동일 패턴)
